# 检索契约（layered evidence reference）

本文件是 gzhu-campus skill 的证据分层与检索规范。SKILL.md 的回答流程按本契约执行；本文件不是第二验证器，规范以 SKILL.md 为准。

## 三层证据

| 层 | 来源 | evidence_role | 标记 |
|---|---|---|---|
| **A 层** | `references/*.md` 中标注"官方已查证"的条目：教务处/学校官网/官方公众号/校历/培养方案/学生手册原文 | primary（结论依据） | `性质：官方已查证` |
| **B 层** | `references/*.md` 中标注"学生经验/一方说法"的条目（小红书/贴吧/B站/抖音/在校生实测）+ 宿主 WebSearch/浏览器联网结果 | supporting / fallback（辅助、补充动态） | `性质：学生经验（一方说法）` |
| **C 层** | 标注"待补充/待核实"的条目 | gap（语料缺口，不构成结论） | `性质：待补充` |

## 分层响应规则

- **`a_primary`**：A 层返回非空时，A 层结论先行；B 层结果仅作辅助，单独成段，不覆盖 A。
- **`b_fallback`**：仅当 A 层检索成功完成、无可用 A 证据、且确需补充信息时使用。回答前必须标注：
  > 未检索到可用的 A 层正式依据；以下结论基于 B 层（学生经验/联网）资料。
  不得把 B 层描述为正式现行政策。
- **语义冲突**：A 层为结论，B 层仅作冲突提醒（例如"空调钟点：官方口径为 XX；学生实测反映为 YY，以宿管公告为准"）。
- **技术失败 ≠ 空检索 ≠ 允许降级**：文件读不到、Grep 报错、脚本失败是技术故障，先修复；不允许因为本地读不出来就用联网结果凑数。
- **时政/人事/临时通知**：高度时效内容若 A 层未收录，宁可说"本知识库未收录，建议查 XX 官网"，也不要用 B 层动态冒充政策。

## 本地检索方法（Grep，无外部依赖）

本 skill 刻意保持纯 Markdown，不引入 Python/SQLite 索引。检索靠 Grep + Read：

1. **核心词**：用 2–6 字核心词，不要长句。例：
   - 问"我想知道转专业需要什么条件" → Grep `转专业`
   - 问"宿舍热水几点有" → Grep `热水`
   - 问"校园跑要跑几次" → Grep `校园跑`
2. **选文件**：
   - 制度/规则/奖学金/违纪 → `rules.md`（大文件，必须 Grep 定位再读上下文）
   - 生活/交通/食堂/快递/学生经验 → `campus_knowledge.md`
   - 专业课程/学分/培养方案 → `academics.md`
   - 开学/放假/考试周 → `calendar.md`
   - 请假/离校报备 → `leave.md`
   - 登录校内系统查个人数据 → `portal-login.md`
3. **最多 4 个去重核心词查询**；空结果缩短核心词重试一次；仍空则报告语料缺口。
4. 命中条目后，**读完整上下文**再回答，不要只摘一行 Grep 结果。

## 条目字段（references/*.md 中每条目的标准结构）

- **位置/入口**：具体地点/URL/楼栋
- **时间/费用**：开放时间、价格、免费/有偿
- **流程要点**：怎么办、找谁、注意事项
- **来源**：URL + 平台 + 年份
- **更新时间**：YYYY-MM-DD
- **性质**：官方已查证 / 地图数据 / 学生经验（一方说法）/ 待补充

## 引用格式

- 每条采信结论后：`【来源：<文档标题>·<章节>】`，附 URL（如有）。
- 有年份/文号必须带上（如"教务处 2026-08-26 通知""2026-2027 第一学期"）。
- 联网 B 层结果：URL + 访问日期。

## 隐私掩码

- 回答中出现的自然人姓名一律替换为 `<某同学>`。
- 不泄露学号、身份证号、手机号、邮箱、宿舍具体门牌号（可写楼栋）。
- 凭证相关（portal-login）：密码绝不写入 references、绝不打印到用户可见输出。

## 贡献准入规则（用户补充数据）

当 A 层未收录或条目标注"待补充"时，可邀请用户补充数据，由 `scripts/contribute.py` 整理为规范条目并发起 PR。准入规则：

1. **三要素必填**：主题（标题）、内容、来源。亲身经历来源写"用户自述（亲身经历，YYYY-MM-DD）"；无来源的条目一律不提交。
2. **分层准入**：默认 B 层（学生经验，一方说法）。仅当来源 URL 落在 `*.gzhu.edu.cn` 等官方域名时才允许 A 层；contribute.py 自动校验，非官方来源请求 A 层时自动降级为 B 并警告。
3. **隐私一票否决**：条目文本不得包含手机号、学号、身份证号、邮箱、疑似密钥、自然人真实姓名（统一 `<某同学>`）。contribute.py 提交前跑与 check.py 同一套正则，命中即终止（退出码 3）。
4. **只发 PR**：贡献进入 `contribute/<文件>-<时间戳>` 分支并发起 PR，绝不直接推送 main；无推送权限时自动 fork 后从 fork 发 PR。合并与否由维护者按 PR 内清单复核决定。
5. **不替代官方核实**：用户补充只填补语料缺口；回答中涉及该条目的结论仍按分层规则呈现（B 层不得覆盖 A 层），并继续提示"以官方最新通知为准"。
6. **自动路由仅为默认值**：目标文件/小节由关键词启发式路由（如"校巴"→ campus_knowledge.md「校车/班车」；带课程字段的评价 → course_eval.md 表格）。AI 调用时应核对路由结果，不确定时用 `section` 字段显式指定。
